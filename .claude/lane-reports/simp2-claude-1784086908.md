## TOP-5 DEEP CUTS (algorithmic, argued)
===========================================================================

### DC1. One broadphase feeding all pairwise-triangle predicates; reuse collider_
Sites: EnumerateSelfCrossings (838), DetectCoplanarClusters (941),
SnapNearCoplanarClusters (2085), RecordSeams (1149). Each independently runs the
IDENTICAL `for i: for j>i` over all triangle pairs with the SAME broadphase
(AABB-overlap + optional shares-vert skip), differing ONLY in the per-pair
predicate body (pierce / filter-coplanar+overlap2D / pairGap+overlap2D /
seam-record). On the dirty path DetectCoplanarClusters and RecordSeams ALWAYS
run back-to-back on the same `in`, so their candidate-pair enumeration is
provably identical and can be a single loop that dispatches to both bodies.
SnapNearCoplanarClusters is a conditional pre-pass but shares the same
enumeration when no near-band exists (the common case, where `in==dirty`
bitwise). The whole family is brute O(F^2); the comment at 837 already concedes
"the collider_ broadphase is the perf path (unbuilt here)". `impl.collider_` is
built at construction and sits unused. Evidence: Twin7081 = 146s in exactly
these loops. Cut = collapse 3-4 O(F^2) sweeps to 1 (or to collider_ queries).
Mechanism savings: dominant runtime + ~2 duplicate scan bodies. This is THE cut.

### DC2. Unify EmitSeamedFace + FoldCoplanarClusters (per-face arrange+classify)
Sites: EmitSeamedFace (1541-1669, ~128 lines), FoldCoplanarClusters (1699-1935,
~236). They share a near-verbatim spine: (a) build the in-plane orthonormal
basis nHat/e1/e2 + `proj` lambda (1550-1561 == 1726-1738, char-identical mod
`a`/`a0`); (b) `getV` dedup-by-3D-bit-pattern into verts2/canon3/vidx (1565-1577
== 1745-1754, identical); (c) `RemoveOverlaps2D(..., &sub)`; (d) map arrangement
positions back to input verts; (e) ExtractCells; (f) largest-sub-triangle pick
(1634-1648 == 1880-1891, identical); (g) RobustWinding classify + emit at
canonical 3D. Only the retention rule genuinely differs (seamed: seam edges +
w_above==0 single-side; fold: cover-mult m + two-side jump self-check + holes).
Extract `ArrangeFaceIn2D(basis, extraEdges) -> {cells, canon3, pts}` and a
`ClassifyAndEmit` policy. Savings: conservatively 60-90 lines and one copy of the
projection/dedup/centroid logic.

### DC3. The gate wants a bool; it computes (and discards) a full labeling - twice
GateComponent (382) calls `DetectCoplanarClusters(comp)` then does
`for (c: ...) if (c>=0) return Dirty` - it needs only "does any coplanar overlap
exist". DetectCoplanarClusters instead runs pass-1 seeding + pass-2 shared-corner
fixpoint extension + rootCount + rootId renumber to produce a per-face id vector,
of which the gate reads one bit. Note pass-2 can never create a cluster without a
pass-1 seed (it requires inCluster(i)||inCluster(j)), so the gate's answer is
exactly pass-1's `any` flag - obtainable with an early-out on the FIRST seeding
unite. Worse, for a coplanar-only-dirty component DetectCoplanarClusters runs
AGAIN in ResolveComponent (2237): full 2-pass labeling computed twice. Cut: a
`HasCoplanarOverlap(comp)` bool (early-out, no pass-2/renumber) for the gate; keep
the labeling for the resolver. On clean inputs (every component hits the gate)
this is a strictly cheaper scan.

### DC4. A single shared TriSoup owning a Box[] broadphase
TriSoup (796) caches tri/vid/lo/hi + BBoxOverlap + SharesVert - and is rebuilt in
DetectCoplanarClusters, SnapNearCoplanarClusters, and (test) EnumerateSelfCrossings
(3 O(F) builds). RecordSeams (1149) does NOT use TriSoup: it re-derives lo/hi
(1159-1168) and re-declares `bboxOverlap`/`sharesVert` lambdas (1191-1200) that
are line-for-line copies of TriSoup's methods, purely because it also wants
faceN + vid stored into BuildArrangement. Have BuildArrangement embed/borrow a
TriSoup (adding faceN), and thread ONE TriSoup through the resolver. Ties into
DC1. Savings: ~25 lines of copy + 2-3 redundant soup builds.

### DC5. EnumerateSelfCrossings/BEnumeration are test-only, re-walking RecordSeams
Confirmed call-graph: EnumerateSelfCrossings (838) + struct BEnumeration (827) are
reached ONLY from EnumerateComponent_Probe (2397), the test hook. Production's
"is it self-intersecting" is impl.IsSelfIntersecting() in the gate; production's
seam geometry is RecordSeams. So ~40 lines of production-namespace O(F^2) scan
exist solely to hand the test a seam count that RecordSeams already computes
(count of A.seamed pairs) or that the DC1-unified scan would expose. Fold the
probe's seamCount/boundaryTouchPairs onto the real scan and delete the parallel
enumerator. (It is a validation pin against fragment numbers - keep the pin, drop
the duplicate mechanism.)

[D5.1] **la::cross for hand-rolled 2D cross** - PROVEN + VALIDATED.
Sites: overlap3.cpp:905, 1674 (`cr` lambdas, body `u.x*v.y - u.y*v.x`), 1525,
1826 (signed-area `p.x*q.y - q.x*p.y`), plus triangle-area cross products at
1580, 1639, 1885. linalg.h:1588 defines `cross(vec2,vec2){return a.x*b.y-a.y*b.x;}`
- literally the same expression; `q.x*p.y`==`p.y*q.x` bitwise (IEEE mul commutes).
Definitionally bitwise-equal, and 31/31 green after substitution. ~6-8 sites, one
concept. Style skill explicitly cites "let linalg do its job" (#1749 x2).

[D2.1] **Box::DoesOverlap for hand-rolled AABB overlap** - PROVEN + VALIDATED.
Sites: TriSoup::BBoxOverlap (815), RecordSeams::bboxOverlap lambda (1191). Both are
`!(hi_i.x<lo_j.x || hi_j.x<lo_i.x || ...)` = `hi_i>=lo_j && hi_j>=lo_i` per axis =
common.h:436 `Box::DoesOverlap` (`min<=box.max && max>=box.min`), same operands,
non-strict, no NaN. Boolean-algebra-equal; 31/31 green. TriSoup should just hold
`Vec<Box>`. Style skill cites Box/Rect reuse (#1722).

[D3.2] **Gate discards the cluster labeling** - see DC3. High value: touches every
clean component.

[D4.1] **Comment volume: design narrative / lab-history in code** - PERVASIVE, one
finding. The style skill (Comments) says move "fuzz history, performance diary,
design narrative, tutorial prose" to docs, and "narration the code already says"
is unwanted. Examples: the SoS block 416-455 (~40 lines of derivation),
"RELUCTANT ACCEPTANCE (owner contract)" 448-455, the "TRIPWIRE ... RELAXED by the
owner to ONE PREDICATE" caller-inventory 710-721, the R1-backstop provenance 1169-
1178, EmitCleanFaces' reg3d-s7b/PokedCube narrative 1943-1967. Much references
notebooks (reg3d-*, v5b-r4, s3/s4adj) that read as private history in a public
file. Keep the one-line contracts + O(n^2) notes; migrate the derivations/history
to docs/Regularize3D.md. Biggest single lever on file size after DC2.

[D2.2] **Projection basis hand-rolled 3x vs GetAxisAlignedProjection precedent**.
Sites: TrianglesOverlap2D (894), EmitSeamedFace (1550), FoldCoplanarClusters
(1726). face_op.cpp:200/238 uses `GetAxisAlignedProjection(normal)` -> `mat2x3`
+ CCW for exactly this "project face to plane 2D". NOT a drop-in: the resolver
needs an e1-EDGE-aligned orthonormal basis so 2D-CCW maps to +nHat (load-bearing
for the retain-orientation argument), whereas GetAxisAlignedProjection is
axis-aligned. So the cut is a LOCAL `PlaneBasis(faceN, edge)` helper (folds into
DC2), not the shared one - but the concept-duplication with face_op is worth a
note for the maintainer.

[D3.1] **EnumerateSelfCrossings test-only** - see DC5.

[D3.3] **Winding seeds duplicated verbatim**. The 6 hardcoded seed vec3s appear at
EmitComponentBoundary (2013-2016) and ClassifyCleanFaces_Probe (2424-2427),
char-identical. A `WindingSeeds(const Box&)` helper removes the copy and the risk
of them drifting. Minor (one is a test hook).

[D4.2] **named namespace `sos`** (456-674). Style skill: named namespaces below
`manifold` "will likely be challenged ... prefers anonymous namespaces as the only
sub-scoping" (#1751). Everything in `sos` is already inside the file's anon
namespace's sibling scope; flatten into the anon namespace with `Sos`-prefixed
names, or leave as a flagged discussion point. Low risk either way.

[D2.3] **WindingAt vs boolean3 Winding03 (conceptual sibling, NOT a cut)**.
boolean3.cpp:388 Winding03_ is the established ray/relative-winding discipline the
doc cites; WindingAt (1028) is its single-soup analogue. They are not mergeable
(two-operand vs one-soup, different escalation), but the maintainer will ask why a
second winding walker exists - pre-empt with a one-line "single-soup analogue of
Winding03; cannot share the two-operand plumbing" contract.

[D2.4] **DecomposeComponents mirrors Manifold::Decompose** (constructors.cpp:455) -
already documented as a deliberate Impl-level copy to avoid a CSG round-trip.
ComposeComponents (2266) hand-rolls MeshGL64 concat. Both acknowledged; no action,
noted for completeness.

[D3.4] **pierce cache documented non-load-bearing** (RecordSeams, 1169-1190). The
comment says it is "verified NON-load-bearing on the shipped corpus ... AND on a
broad general-position sphere family" yet kept as an R1 backstop. A whole std::map
kept as a proven-inert safety net is a YAGNI flag - but the owner explicitly
retained it. Leave; noted.

[D1.x smaller] **largest-sub-triangle pick** duplicated (EmitSeamedFace 1634-1648,
FoldCoplanarClusters 1880-1891) - folds into DC2. **signed-area** inlined in
ExtractCells (1522-1526) and as `loopArea` in FoldCoplanarClusters (1822-1829) -
share one helper (with D5.1 la::cross).

[D5.2] **SegPlanePoint -> la::lerp: REJECTED (not bitwise)**. `u+(t)*(v-u)` vs
linalg lerp `a*(1-t)+b*t` (linalg.h:471) differ in rounding. Do NOT convert - it
would perturb pierce coordinates that the once-only cache relies on. Recorded so
the Codex lane and synthesis don't re-propose it.
