### Step 1: PROBE the real carriers' anatomy (env-gated instrumentation) - DONE

Instrumented EmitSeamedFace (per-cell 2D thinness + classify), BuildImpl (weld +
failure mode), SplitTouchingSheets (failure branch), plus a winding-grid + inline
Van Oosterom-Strackee GWN cross-check. MEASURED (PokedCube + GT7863-comp1):

- EMITTED TRIANGLES ARE FAT. min altitude billions-of-eps (PokedCube), millions-of-
  eps (GT7863). ZERO sub-eps cells. ZERO degenerate edges. ZERO coincident centroids.
  Every per-face 2D cell has minWidth >> eps. THE PREMISE (sub-eps slivers) IS ABSENT.
- BOTH fail at BuildImpl -> SplitTouchingSheets -> "unbalanced fwd/bwd, fanSize=1" =
  an OPEN BOUNDARY EDGE (a single unpaired halfedge). The emitted {w>=1} surface is
  NOT CLOSED. Not a touching-sheet / thin-cell issue - a HOLE.
- ROOT CAUSE: cells classifying to w_above = -1 (NEGATIVE winding) are DROPPED by the
  mult-1 witness rule (w_below = w_above+1 = 0, both exterior => correct per-cell drop).
  The dropped cells leave the hole. Confirmed w_above = -1 STABLE across nudge scales
  0.5..256 eps (NOT a thin-slab straddle artifact).
- INDEPENDENT ORACLE: Van Oosterom-Strackee GWN at each classify point AGREES exactly
  with RobustWinding (PokedCube dropped cells GWN=-1.0000; GT7863 dropped GWN=-1.0000).
  So the negative winding is REAL GEOMETRY, not a winding-computation bug.
- WGRID (21^3): PokedCube has a MACROSCOPIC w=-1 region (619 pts ~ same size as w=1's
  662). GT7863's two components are winding {0,1} on the coarse grid, but a real (grid-
  subsampled, oracle-confirmed) thin w=-1 region sits at face 60.

VERDICT: PokedCube and GT7863 are NOT thin-cell carriers. Their wall is NEGATIVE
WINDING (w_S reaching -1) creating d{w>=1} boundary structure (w=-1 adjacent to w=1,
a winding jump of 2 / double-sheet) that the mult-1 per-face emission cannot close ->
open boundary -> fail-closed. This is the openscad-class subtraction axis, which
docs/Regularize3D.md lists SEPARATELY ("NEGATIVE WINDING / subtraction, untested"),
NOT stage-7 thin-cell. Extends the near-coplanar memo's correction (GT7863 is exact-
coplanar, not near-coplanar). The stage-6/s6 re-attribution to thin-cell is refuted
by measurement. Probe instrumentation is temporary (to be reverted; v3 sweep untouched).

### Step 2: is the thin-cell wall REACHABLE at all? - DISSOLVES

Tried to CONSTRUCT an escaping thin cell: a floor face crossed by a TRANSVERSAL
(90deg, not near-coplanar) wall whose floor-seam splits off a 0.4-eps-wide strip,
with NO face near-coplanar to the wall (so stage-5 cannot fold it). Result: the
open soup was rejected by Impl construction (needs a closed manifold); more
importantly the structural reasoning + the EXISTING stage-5 fixtures settle it:

- The ONLY reachable source of a sub-eps thin cell is NEAR-COPLANAR sheets (gap <
  eps in the NORMAL direction). This is EXACTLY the stage-5 NearSlantPlug family
  (test comment: "Without the widen this fails closed at the SLIVER EMISSION; the
  snap folds it"). Stage-5's input-side planarization (SnapNearCoplanarClusters)
  IS the thin-cell resolution for this case, LANDED, and Regularize_NearCoplanar*
  (Mult2 / AntiCancellation / GuardFailClosed) are GREEN. Mutation-verified in s5
  (disable snap -> sliver fail-closed).
- A TRANSVERSAL sub-eps sliver (seam within eps of a floor edge, wall NOT near-
  coplanar) has NO failure regime: gap < eps -> the seam pierce points weld onto
  the existing edge verts (eps-weld absorption, the SweepEmit3D [D3-R5] delegate-
  to-vert-merge precedent) -> resolves; gap > eps -> the cell is representable.
  There is no width that both escapes stage-5 AND fails at emission.
- A thin cell from NEAR-CONCURRENT transversal seams is a NEAR-TRIPLE-POINT = the
  separately-named >2-sheet triple-point axis (openscad), not thin-cell.

=> The "stage-7 thin-cell emission" wall, as a DISTINCT residual axis, is EMPTY.
It decomposes entirely into: near-coplanar (stage-5, LANDED) + eps-weld absorption

dirty-component carrier triggers the thin-cell hole."

### Step 4: PLANE-BASED REPRESENTATION probe spec (owner's pre-agreed escalation)

The in-B thin-cell winding-merge (task candidate (a)) has NO valid carrier (step 1-2:
zero sub-eps cells on the real carriers; the only reachable thin cells are stage-5's).
Forcing it would be a gross mechanism on a non-problem -> ESCALATE, as pre-agreed.

WHAT IT IS. Every constructed arrangement vertex (pierce point, triple point) is
carried SYMBOLICALLY as an INPUT-PLANE TRIPLE {P_i,P_j,P_k} (P = a quantized input
face's supporting plane, exact-integer coeffs), not a rounded vec3. Input verts are
trivial triples. ALL arrangement decisions (cell membership, radial order, coupled
winding, thin-cell retention) are exact predicates (plane-coefficient determinants).
Coordinates round to double ONCE, at final emission. This is per-face 2D + coupled
winding UNCHANGED (only the vertex TYPE changes vec3 -> triple), so it does NOT
re-trigger candidate (b)'s global-3D-complex cost kill.

WHAT IT BUYS (checked against the measurement):
- R1 WELD-TWIN RETIRE (doc R1, the acknowledged open residual). Coincident-by-
  construction points share ONE triple => EXACTLY equal symbols => emission emits one
  vertex, never two rounded twins. The uniform eps-weld (which R1 says can merge two
  exact-distinct points or split coincident ones) is REPLACED by symbolic identity
  (merge iff same triple). Once-only construction (R1) is SUBSUMED (triple canonical
  by sorted plane-id set).
- EXACT TRIPLE POINTS (axis 2). A triple point IS a plane triple; the ">2-sheet /
  new-crossing-vertex -> fail closed" branch in EmitSeamedFace becomes decidable.
- THIN-CELL AT ROUNDING (owner's framing). Cell thickness = exact predicate on the
  bounding triples; "rounds to degenerate at double?" decided ONCE at rounding, the
  retention/merge chosen symbolically BEFORE geometry exists. Lets stage-5's input-
  snap be REPLACED by an at-rounding decision (no input perturbation). NOTE: this
  case is EMPTY on reachable carriers (stage-5 covers it) -> UNIFICATION, not a fix.

WHAT IT DOES NOT BUY (honest): NEGATIVE WINDING (the dominant residue). That is a
witness-rule classification completion, ORTHOGONAL to vertex precision. The rep does
not close PokedCube/GT7863.

COST / KILL-TABLE. Crosses the doc's EXACT-KERNEL TRIPWIRE: it needs MULTIPLE new
exact predicates (plane^3 intersection sign, in-cell, thickness) at multiple sites,
past the "ONE predicate at ONE call site" limit -> honest precondition is VENDOR
Shewchuk predicates.c first (the doc's own instruction), not grow the integer path.
That vendor step is the real price the owner must weigh.

DECISIVE GO/NO-GO PROBE (a stage-8 lane must run BEFORE committing):
1. Corpus (siA/siB + GT7863 + openscad): histogram arrangement verts by plane-count
   {input, 2-plane pierce, >=3-plane triple}. Doc claims ZERO genuine triple points

   also verified NON-load-bearing (s2/s3) => BOTH payoffs untriggered on real data =>
   the rep is all-insurance, no measured RED it fixes. That is the no-go signal.
2. Count the distinct exact predicates the rep needs (validate the tripwire crossing;

3. Red-first R1: construct the near-parallel tail where two exact-distinct arrangement

VERDICT: the plane-based rep is the correct LONG-TERM substrate for R1 + triple-points,
