## Step 2: understand M4 one-arrangement approach

SweepCapture has (from, to, sourceId) - no winding value.
For ONE arrangement approach: L edges get srcId = L_TAG, R edges get srcId = R_TAG.
After ONE RemoveOverlaps2D call:
- The output edges are oriented interior-on-left
- An edge with srcId=L_TAG retained means it bounds cap_plus (L inside, R outside)
- An edge with srcId=R_TAG retained means it bounds cap_minus (R inside, L outside)
- But L and R share boundaries where L-caps-R - those subdivided edges need separate classification

Actually the simplest faithful approach:
- Run ONE RemoveOverlaps2D(rawVerts, L(+1)+R(-1)) -> OverlapResult with shared verts
- From r.verts (the ONE consistent snap), run two separate OutEdgesToPolygons:
  - L_cap_plus edges: those from the L set that survived (winding = +1 interior)
  - R_cap_minus edges: those from the R set that survived (winding = -1 interior)
- But RemoveOverlaps2D with WindRule::Add retains ALL boundary (both winding=+1 and winding=-1)
  in the same output edge set

Plan: classify retained edges by their mult sign:
- retained edge with net mult +1 -> bounds cap_plus (L region)
- retained edge with net mult -1 -> bounds cap_minus (R region)
But OverlapResult::edges uses OutEdge = EdgeM which has mult field...

Let me check what mult value retained edges carry.
