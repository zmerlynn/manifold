## 5. GUARD SEMANTICS (contract-eps vs identity-eps) - one paragraph for the memo

The eps in SnapNearCoplanarClusters (pairGap<eps clustering, <=eps snap-to-plane,
max-dev>eps global-planarity fail-closed), the winding-probe offset (cen +- eps*nHat),
and GateComponent's 2*eps IsSelfIntersecting relaxation are NOT identity decisions
and must NOT be retired with the merges. They implement the eps-VALIDITY CONTRACT:
the standing promise that the input is an eps-valid mesh, so features thinner than
eps are geometrically indistinguishable from coincident and the operator is licensed
to snap/probe/relax within an eps ball. That is a statement about the INPUT's
resolution, not about whether two constructed points are the SAME point. Identity-eps
(S1-S5) asks "are these the same vertex?" - a question once-only construction answers
exactly (bit-equal) and level-0 incidence answers exactly (aliasing), so it retires.
Contract-eps asks "is this feature below the input's representable scale?" - a
question that has no exact answer because the input itself is only eps-accurate, so
it STAYS. Confusing the two would either (a) delete the near-coplanar snap and
re-admit the sub-eps thin cells the arrangement cannot carry, or (b) keep a distance
weld that once-only has already made redundant. The retirement touches only
identity-eps; every contract-eps site is marked KEEP.
