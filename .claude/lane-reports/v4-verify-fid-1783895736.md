## ATTACK R5 - variant-(i) incremental drift on a REAL incremental structure

Doc's variant-(i) drift objection rests on probe 2's BATCH surrogate. R5: build a
minimal REAL incremental 1D order-maintenance KDS over a nextafter-spaced
near-coincident event stream; measure whether the incremental resolution depends
on event-processing order, and whether a from-input recertification recovers batch.

Files: scratchpad/r5_group.cpp (single pencil, printed), r5_seed.cpp (8 pencils).
Model: K=9 lines through a near-pencil at (x0~1e-9, ~0), distinct slopes, sub-eps
intercept spread -> all C(9,2)=36 crossings cluster in a ~5.9-eps band. A kinetic
sorted list sweeps x, firing adjacent crossings; each fired crossing CONSTRUCTS a
shared vertex (block-rule collapse = snap the crossing point to a construction
grid). Metric = the GROUPING: the set of distinct shared vertices (spread-vs-
distinct), which is the doc's actual near-degeneracy RESOLUTION - not the final
sort order (with fixed slopes the order is always slope-determined = batch, so it
cannot show drift; the resolution lives in the grouping).

- Mode A (CONSTRUCTED): crossing point read from running (overwritten) intercepts;
  firing overwrites both elements' intercepts through the snap -> later snaps
  consume constructed coords.
- Mode B (FROM-INPUT RECERT): crossing point re-derived from ORIGINAL coords;
  running state never consumed for the snap.
- Event order varied by the tie-break among near-coincident (|dx|<tau) events
  (the doc's "sub-eps certificate reordering"), T1=low-pair-first, T2=high-first.

RESULT (single pencil): BATCH = 5 shared vertices at y/eps [-3, -0.96, 0.09, 1.2,
3.6]. Mode A: T1 -> 9 vertices, T2 -> 15 vertices (positions run to -24.9 eps),
A(T1)!=A(T2), A!=batch. Mode B: T1 and T2 both -> exactly 5 vertices == batch.

RESULT (8 pencils, r5_seed): A drifts 8/8 (grouping count swings from batch's 5-7
to 8-18, order-dependent, positions run away tens of eps); B recovers batch 8/8.

### R5 verdict: BOTH - DRIFT-CONFIRMED and RECERTIFICATION-RECOVERS.
- The drift objection to variant (i) is REAL and severe on a real incremental
  structure: a naive constructed-coordinate KDS gives an order-dependent grouping
  that diverges MACROSCOPICALLY (the spread-vs-distinct count itself is not
  well-defined). Not a rounding nuisance - matches probe 2's "macro" claim, now
  without the batch surrogate.
- BUT a from-input recertification rule restores EXACT batch-equivalence (order-
  free), so variant (i) IS viable under the precondition: re-derive every
  certificate/snap from ORIGINAL input coordinates, never from updated state.
- The honest caveat (keeps the doc's convergent verdict intact): from-input recert
  of the GROUPING = clustering all from-input crossings at once = the BATCH/global
  collapse = variant (iii). So (i) recovers robustness precisely by REDUCING to
  (iii); the incremental machinery buys nothing. This is exactly the doc's "make
  the decision ONCE and flow it downstream" - R5 makes it empirical: naive (i)
  drifts, correct (i) IS (iii). The doc slightly OVERSTATES that (i) "trades away"
  the batch's robustness with no recovery; the sharper statement is (i) must recert
  from input to be correct, and that recert collapses it into (iii).
