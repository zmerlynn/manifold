## Stage-2 handoff: what candidate B's production core needs next

The Stage-1 seam is `RunCandidateB(const Manifold::Impl& dirty, double eps)` in
src/overlap3.cpp (a fail-closed stub). B replaces the stub body; the caller's
re-gate (step 5) and compose-back (step 6) already stand. When B lands, DELETE
`FatalReason::DirtyComponentUnresolved` uses on the happy path and ENABLE the
DISABLED_ pin `Overlap3.DISABLED_Regularize_DirtySingleComponent_Regularized`
(its acceptance criteria: fatal-free, counters.regularized==1, valid manifold,
output NOT IsSelfIntersecting). What B must build, per docs/Regularize3D.md
"B's mechanism" (validated at fragment scale, see the v5b lane notebooks):

1. ENUMERATION - collider broadphase (reuse `dirty.collider_`, already built)
   over the component's own faces; keep genuine non-adjacent crossings, skip
   shared-vertex pairs. Every crossing DECISION a level-0 orient2d/orient3d on
   input coords through a static Shewchuk filter; exact fallback only on filtered
   uncertainty (v5b-s12: filter proven sound). Reuse Canonicalize
   (overlap3.cpp:218) for the signed-multiplicity fold (winding delta sign =
   CanonicalFace.mult x crossed-face orientation).
2. WINDING - per-cell integer w_S by signed face-crossing deltas, coupled across
   the arrangement (unite non-crossing edges, one seed ray per connected cell-
   component, flood; the Winding03 discipline, boolean3.cpp:388). Deltas are +-1,
   FP-safe by construction. COST: each seed cast is O(ntri) scoped to the
   component; a large component (GT7081-scale) pays seconds-per-query -> needs the
   component-local seed policy (a named open) and, for perf, an adaptive orient3d
   kernel that does not exist in the tree today (net-new surface).
3. ASSEMBLY (THE BUILD - largest unbuilt piece) - build the arrangement cell
   complex, radial-order halfedges around each arrangement edge (2-sheet trivial
   on the corpus; the >2-sheet determinant rule is specified but unforced),
   classify each cell by integer w_S, EMIT the oriented halfedge boundary of
   {w_S >= 1}. The fragment did point-classification of recorded cells, not the
   boundary build. ONCE-ONLY construction is a required design element (each
   intersection built once, referenced everywhere) - not advice.
4. UNEXERCISED axes to carry as opens (docs/Regularize3D.md "Open list"): single
   global SoS for cross-operand vertex-on-face ties (GT7863/openscad), negative-
   winding/subtraction absorption, once-only under a genuine triple point.
5. R1/R2 residual (the weld-fold blind spot): B's own once-only construction +
   radial assembly is the structural defense (no O(seam^2) projected twins); the
   uniform assembly weld in ComposeComponents/BuildImpl must NOT merge two
   genuinely-distinct arrangement points that round within eps. The re-gate does
   not backstop a weld-manufactured fold (shares-vertex skip hides it). Left open.

NOTE: ComposeComponents currently concatenates through MeshGL64 (a fusion-free
path, per the touching-contact fixtures). If B's per-component output must weld
INTERNALLY, that weld belongs inside B (before its re-gate), not in the cross-
component compose-back, which must stay fusion-free.
