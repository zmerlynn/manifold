## Structural read of boolean3 FIRST (src/boolean3.cpp + src/shared.h)

The core predicate is `Shadows(p,q,dir)` (shared.h:121):
```
inline bool Shadows(double p, double q, double dir){ return p==q ? dir<0 : p<q; }
```
This is the WHOLE decision structure. boolean3 never forms a 3x3 orientation
determinant. It decomposes every geometric decision into a cascade of 1D
comparisons on double coordinates:
- Shadow01: pair of `Shadows(x_a, x_b, ...)` on the X coordinate (edge/vert
  overlap in a projected axis), plus a Y `Shadows`.
- Kernel02 / Kernel11: sum a few Shadow01 results (s02, s11 counts) then a final
  Z `Shadows`.
- Kernel12: sums k02 + k11 crossings -> x12 count; sign of that integer count is
  the topological decision.
- Winding03: sums Kernel02 signs into per-vertex winding integers, flood-filled.

Ties (p==q exactly) are broken by `dir` = a sum of face-normal components
(Simulation-of-Simplicity-flavored symbolic convention), gated by `expandP`
(true for union/Add, false for difference/intersection) via
`withSign(expandP,v)=pos?v:-v`. ZERO exact escalation (matches the grep claim).

CONSEQUENCE / HYPOTHESIS: because the decisions are 1D double comparisons, the
"determinant that goes below the certified float bound" framing does not map onto
boolean3 the way it maps onto a 3D orientation kernel. The quantity that gets
small is the GAP between two coordinates being compared, and `p<q` on doubles is
EXACT whenever p!=q. The only place error enters is (1) the CONSTRUCTED
intersection coordinates (Interpolate/Intersect in shared.h, which do carry FP
error and feed the NEXT level's Shadows), and (2) the tie convention when p==q.
So the prediction is: boolean3 stays topologically clean always, and stays
geometrically right as long as the INPUT coordinate comparisons are exact; the
question is whether constructed-coordinate error at deep conditioning flips a
downstream Shadows and moves material. That is what the sweep tests.

## VERDICT

NO geometric/material cliff in ANY family, down to and PAST float capability
(1e-16 deg, gap 1e-16). Membership mismatches = 0/533 in EVERY run across all 4
families, both union and difference, and intersection. boolean3 is
manifold + SI-free + geometrically CORRECT throughout.

The err_over_sliver metric crosses 1 (family a below 1e-11 deg, family b below
~1e-10 gap) ONLY because the sliver/slab volume shrinks below Volume()'s own
float rounding floor (~coord^1 * eps ~ 1e-10..1e-12 absolute). The ABSOLUTE
volume error tracks that rounding floor, not a growing geometric mistake, and
membership stays perfect - the sub-eps sliver simply COLLAPSES to clean geometry
(ntri drops 66->20; output becomes a single clean wall/box). Collapsing a
1e-13-thick slab at coordinate 150 is CORRECT: that feature is not representable
in doubles, so a single merged solid is the right answer. Worst honest geometric
error: family (b) gap 1e-11, abs vol err 2.0e-7 (2x the vanishing slab) yet
membership-clean; family (a) diff 1e-10 deg, rel_err 1.1e-4 on a 2e-7 volume.

WHY boolean3 stays right (mechanism, from the source read): every decision is a
1D `Shadows(p,q,dir)= p==q?dir<0:p<q` on double coordinates. `p<q` is EXACT for
p!=q, so INPUT-coordinate comparisons never err regardless of how small the gap.
It never forms a 3D orientation determinant, so there is no "determinant below
the certified float bound" to go wrong - the campaign's near-eps-determinant
failure mode does not exist in boolean3's decision structure. Error can only
enter via CONSTRUCTED intersection coords (Interpolate/Intersect) feeding a
downstream Shadows, or via the tie branch when p==q; in these families neither
flips a macroscopic decision because the constructed coords stay on the correct
side of the next comparison (the geometry that would flip it is itself sub-eps
and collapses). Determinism: bit-identical across re-runs even with TBB PAR=ON
(run2_bitident=1 always). Operand-order sensitivity (A+B != B+A bitwise) appears
ONLY in the wedge family at theta <= 1e-8 deg, by sub-sliver amounts (1e-10..
1e-13), both answers within exact error and membership-identical - the symbolic
tie convention (expandP) is order-dependent in the near-tie regime but
geometrically inconsequential.

## CONTEXT for the campaign
(a) boolean3-as-oracle validity: for near-degenerate UNION/DIFF/INTERSECT of
realistic geometry it is a SOUND geometric oracle to machine precision - it does
not silently place wrong material. Its output can be trusted for membership /
extent ground truth in exactly the conditioning band (near-parallel walls,
coincident faces, sub-eps gaps) that GT7081/openscad live in. The caveat is
scope: it guarantees manifold + membership-correct-to-representability, NOT that
it preserves a sub-eps feature you care about (it will collapse it). If our
closure work needs to DISTINGUISH features below ~coordinate*eps, boolean3 will
have already merged them - so it is an oracle for "is this solid right", not for
"did the sub-eps sliver survive".
(b) upstream hardening: NOT warranted for geometric correctness - boolean3's
1D-comparison structure already sidesteps the bad-determinant mode our exact
kernel exists to catch. Our Orient3DExactSign is a 3D orientation predicate;
boolean3 computes no orientations, so it is not a drop-in. Hardening boolean3
would mean making Interpolate/Intersect exact (rational 1D/2D construction +
exact compare) - a DIFFERENT exact-kernel family, and the measurement says it
would buy nothing here. Recommend: do not build.
