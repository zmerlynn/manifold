## METHOD (offline exact-rational oracle, ported from f4-r4/r5 at the NEW state)

Instrumented the COPY (env F4R_DUMPFILE, lossless %a hex) to dump, per resolved
component: the SNAPPED input mesh `in` (verts + tris + seamed flag) and the
pre-BuildImpl emitted soup with per-tri provenance (fold / seamed-face-f /
clean). oracle.py (Fractions; doubles are dyadic -> exact):
  1. Replicates BuildImpl eps-weld (min-index 3x3x3 grid, double math) +
     degen/dup filter BIT-EXACT -> welded verts + tv (tri index == the
     F4B_OPENEDGE `faces=[..]`).
  2. Replicates SplitTouchingSheets open-edge detection -> 18 opens, fan dist
     {1:11, 3:6, 4:1}, matching F4B_CENSUS exactly (welded verts 1468, kept tris
     2957 of 2962 emitted).
  3. Exact ray-cast winding wS(Q) over `in` (generic rational ray, float
     pre-filter with exact fallback on the near-coplanar cluster). Calibrated:
     wS(far)=0; mult-1 emitted boundaries show a clean 0|1 jump. Solid = {wS>=1}.
  4. Per open edge: exact circular fan reconstruction. Solve exactly for each
     input face plane's two crossing angles of the radius-r perpendicular circle
     around the edge axis; sort events; sample wS once per interval. Yields the
     TRUE {wS>=1} boundary carriers around each edge, each carrier's input face +
     signed plane offset, marked EMIT (in the open fan) or MISS (absent partner).

Validated against the census and against the in-tree EX2_CELLDUMP retention
values below.

## (1) TRUE PARTNER, per edge - the exact {wS>=1} boundary

For every one of the 18, the emitting face keeps a genuine mult-1 boundary cell
(EX2_CELLDUMP: w+=0 w-=1 keep=1). The TRUE reverse partner at the shared edge is
a cell on a DIFFERENT, coincident-or-near-tangent input face (the partner column).
That partner cell IS built (EX2_CELLDUMP shows n=3..6 cells per partner face) and
its centroid winding is BURIED (w+=1 w-=2) or EXTERIOR (w+=-1 w-=0), so per-face
retention drops it (keep=0). Two coincident cells, one kept (boundary at its
centroid) and one dropped (buried at its centroid), share the open edge -> it is
emitted one-sided. fan2=0 corpus-wide confirms the partner is genuinely ABSENT,
never mispaired.

The fan3/fan4 edges (E04,E05,E07,E11,E13,E17) are the higher-multiplicity nodes
of the same cluster (3-4 coincident seamed walls meeting), imbalanced by one
absent partner - not a distinct mechanism.

## (2) PRODUCTION GAP - walked per partner sub-face, first losing step named

- SUBDIVISION: NOT the loss. The partner face's arrangement already subdivides at
  the 22-eps structure. Under DEFAULT (RemoveOverlaps2D) the near-tangent
  crossings (>= 22 eps > eps) are not merged, so the partner cell is bounded;
  under the input-exact overlay flagged on exactly these faces, splitsAdded=0 (the
  crossing set is already registered). Subdivision is complete either way.
- CELL BUILT: YES, under both default and the overlay lever (EX2_CELLDUMP;
  fracture-1784218577: 378 cells built across the flagged cluster faces).
- RETAINED: NO. FIRST LOSING STEP. EmitSeamedFace classify, overlap3.cpp:5016-5017
  RobustWinding(in, cen3 +/- eps*nHat, seeds) -> :5023 BothSidesRetain (rule
  :3870) -> :5032 `if (keep == 0) continue;`. The partner cell centroid probes
  BURIED (w+=1/w-=2 -> both sides in {wS>=1}) or EXTERIOR (w+=-1/w-=0 -> both out),
  so keep=0. This drop is INDIVIDUALLY CORRECT per the witness rule and per
  floodclose (the probe is exact winding at the cell centroid; the +/-eps*nHat
  offset cannot cross a 22-eps-distant sheet), but it is NOT edge-consistent: the
  same cell's EDGE at the open location is a manifold boundary the per-face
  centroid decision cannot see.
- For B2 (3 edges) there is a SECOND gap even if retained: the partner is a
  genuinely-distinct near-tangent sheet > eps away, so the eps weld
  (BuildImpl getVertIdx, radius eps, overlap3.cpp:~296) would not merge its edge
  onto the open edge. Loss = retention AND weld.

## FIX SHAPE + HONEST SCOPE

The losing step is RETENTION, not subdivision or build, so the overlay/coverage
half (in-tree, inert) does not help - confirmed by the experiment. The fix is the
E1 PAIR/synthesis half:
  - a CLUSTER-GLOBAL shared cell complex (coincident faces share the sub-edge by
    identity, not per-face independent copies), and
  - PER-EDGE coordinated retention: decide the {wS>=1} boundary ONCE per shared
    sub-edge across all coincident sheets (so the thin cell's boundary role is
    edge-consistent, not read off one cell centroid), and
  - near-coincident distinct-sheet weld/synthesis for B2 (emit the thin connecting
    cell or coarsen the shared boundary the eps weld cannot merge).
Scope (fracture-1784218577 pricing): ~400-800 LOC net-new, the PAIR/synthesis
half of the E1 engine. NOT the smaller "coverage of partner faces + in-tree
overlay + retention-as-is" hypothesis (measured-refuted: 18 -> 28/33). NOT a
predicate degree (depth-1 kernel suffices; the winding/pairing is combinatorial).
Sharpening: 15/18 (B1) need only the per-edge retention coordination (partner
within weld radius, no new geometry); 3/18 (B2) additionally need the
distinct-sheet weld/synthesis.
