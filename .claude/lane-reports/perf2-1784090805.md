## Baseline profile (seq build, 1 thread) - where the time goes

Env-gated profiler (REG3D_PROFILE=1) times each resolve phase + counts winding
work. siA (17160 tri, 1 dirty component):

    snap=155 detectCoplanar=164 recordSeams=259 seamed=354
    cleanFaces=8822  build=77    (ms)   windCalls=17498  windTriIters=300,265,680

cleanFaces (the per-clean-face O(nTri) winding walk) is ~88% of the resolve;
17498 walks x 17160 tri = 300M orient3d-filter iterations. This is the doc's
named "winding-query perf axis" and the wall-clock item, confirmed empirically.
Both gimmes target it.

Baselines: openscad 1440tri ~207ms; siA ~9.9s; siB ~9.1s; GT7081 31360tri ~69s.

## GIMME 1 - winding-query BVH broadphase  (THE TOP WIN)

REG3D_WIND_BVH=1. A per-component Morton-sorted triangle Collider (built once in
EmitCleanFaces). Each winding ray p->seed queries the collider with the SEGMENT
AABB Box(p,seed) -> the candidate triangles it could cross (a superset). Same
far-diagonal seeds, same exact per-triangle predicate chain
(WindingCrossTri), only the iteration set shrinks. Validation mode
(REG3D_WIND_VALIDATE=1) runs BOTH the broadphase and the O(nTri) walk per query
and tallies disagreements (windDiverge).

Phase-level (seq build, within-run ratios):

    fixture  cleanFaces base -> bvh   candidates (walk -> bvh)   windDiverge
    siA      15527 ms   -> 2592 ms    300.3M -> 46.1M  (6.5x)    0
    siB      ~19000 ms  -> 3170 ms    300.3M -> 40.5M  (7.4x)    0
    GT7081   21906 ms(*) ...           511.4M -> 64.9M  (7.9x)    0

Overall (seq build): siA 17.6s -> 4.5s; siB ~9-12s -> 5.3s.
(*) GT7081 cleanFaces figure was measured under concurrent build load; use the
candidate ratio (7.9x) and windDiverge=0 as the robust facts.

The segment-AABB superset is far MORE effective than a naive octant estimate
would suggest (6-8x fewer candidates) because these fixtures are thin, near-flat
shells: from an interior point most triangles' AABBs don't overlap the ray box.

Correctness (bitwise): windDiverge=0 on siA/siB/GT7081. overlap3 light suite
27/27 identical with bvh AND bvh+validate. siA/siB Regularize_* tests (exact
volume/manifold assertions) pass with bvh on. Output FNV checksum identical
baseline vs bvh (siA 1ed55c36763ab73e, siB e0ca1a48ae11b76d, GT7081
d84aa5a81d6db015).

Honest caveat (know before landing): the bbox broadphase is a superset of the
ray's CROSSINGS, not of the walk's plane-coincidence ties. The O(nTri) walk
re-seeds (returns nullopt) if p or seed lies exactly on ANY triangle's plane,
including a distant triangle the ray never crosses; the broadphase skips that
distant triangle and would NOT re-seed. Measured windDiverge=0 everywhere (it
never fired), but the winding value in that corner is the more-correct one, not
a bitwise match of the walk's nullopt. If productionized, either accept this
(it is strictly more permissive / never wrong) or keep the O(nTri) tie-scan.

## GIMME 2 - parallelism (PAR build, TBB)

Order-freeness is real (independent per-face / per-component work). All variants
are two-pass (parallel classify -> sequential in-index reduce) so output is
bitwise-identical regardless of thread count.

2a - parallel clean-face classification (REG3D_PAR_CLEAN=1). cleanFaces phase,
siA, bvh on:

    threads   1      2       4       8
    cleanFaces 3474  1696    1528    1401   ms
    speedup    1.0x  2.05x   2.27x   2.30x

Scales ~2x at 2 threads then PLATEAUS - memory-bandwidth / malloc-bound (each
winding query allocates a candidate std::vector). A thread-local reusable
candidate buffer would likely lift this (NAMED, not built). And because the BVH
already shrank cleanFaces, the un-parallelized serial phases
(snap/detectCoplanar/recordSeams/seamed) are now the floor, capping the overall
benefit of parallel-clean on single-component fixtures.

2c - parallel component dispatch (REG3D_PAR_COMPONENT=1). Only helps inputs with
several DIRTY components. GT7081 has 2 dirty shells; running them concurrently:

    GT7081   baseline-1t   bvh-1t   bvh+par(comp+clean)-4t
    time     85.1 s        65.4 s   43.5 s
             (1.0x)        (1.30x)  (1.96x)     csum d84aa5a81d6db015 all three

siA/siB are single-component: 2c does nothing for them.

Full-suite correctness with ALL gimmes on (bvh+par_clean+par_component, 4
threads, PAR build): overlap3 31/31 PASS. Default env-off through the refactored
sequential paths: overlap3 31/31 PASS (behavior unchanged).

Determinism rail VERIFIED: FNV output checksum identical across baseline / bvh /
1/2/4/8 threads / 3 reps, on siA, siB, GT7081, openscad. openscad fail-closes
identically (comp=2 reg=1 fail=1) with gimmes on.

## Combined picture (PAR build, all csums identical)

    fixture  baseline-1t   bvh-1t    bvh+par-4t     note
    siA      18.7 s        8.5 s     4.0 s (4.6x)   PAR 1t is TBB-inflated
    siB      18.5 s        5.4 s     3.2 s (5.9x)
    GT7081   85.1 s        65.4 s    43.5 s (1.96x) recordSeams-bound

NB: the PAR build's single-thread baseline is ~2x the seq build's (TBB per-op
overhead). Against the SEQ production baseline (siA ~10s) the winding BVH alone
(seq, ~4.5s) is the honest headline; parallelism adds a modest further factor
that must first pay off the PAR-build overhead.

## What is NOT a gimme (named, not built)

- recordSeams O(F^2) seam enumeration: after the BVH it is the dominant GT7081
  phase (~47s under load). This is the FOLD LANE's unified-broadphase item
  (skipped here per instructions). Once it lands, gimme-1 + gimme-2 compound.
- seamed-face emission parallelism: the once-only pierce-point construction
  table (doc R1) is shared mutable state across faces. Parallelizing needs a
  pre-enumerated two-pass pierce table (or mutex) = real design, not a drop-in.
- winding-query allocator pressure: thread-local candidate buffer to unstick the
  ~2x plateau. Small, but a design choice (thread-local lifetime), not a gimme.

## Bottom line

Gimme 1 (winding BVH) is real and bitwise-safe: 6-8x fewer winding candidates,
~4x on siA/siB single-thread, windDiverge=0, output checksum-identical. Gimme 2
(parallelism) is real but secondary on this hardware: ~2.3x on the clean-face
phase (plateaus, malloc-bound), ~2x on GT7081 via component parallelism,
determinism verified. The next unlock is the fold lane's seam broadphase, after
which both gimmes compound.
