## 1. DEPTH CENSUS (every decision the cluster-local closure needs)

Basis choice: the evaluator's GENERATORS are the double PLANE COEFFICIENTS
(nx,ny,nz,d) for constructed points and the double VERTEX COORDS for input
points, each an exact integer M*2^E (frexp, |M|<2^53) - the SAME rounded doubles
Intersect3Planes / the mesh commit to. We do NOT use the input-coordinate basis
(where a plane is degree 2 in n / degree 3 in d, so a plane triple is degree 6-7
and orient2d degree ~21): that basis would re-derive planes symbolically and
DIVERGE from the double-rounded plane coefficients the rest of the pipeline uses,
breaking incidence-by-construction with the committed geometry. Degrees below are
in the plane-coefficient basis; the input-coordinate degree is ~2.3x (each plane
coeff degree 2-3 in inputs) and is recorded per row where the theory lanes need
it.

## 2. THE EVALUATOR (HomogEval, depth-parameterized)

Design (prototype: /tmp/depthk/depthk_harness/depthk.cpp, namespace bi):
- A homogeneous coordinate is carried as an EXACT INTEGER bigint: sign-magnitude
  little-endian limbs + a single binary exponent e (value = sign*mag*2^e), seeded
  by frexp EXACTLY as DecomposeH (M*2^E). Ops: Mul (schoolbook mag multiply, e
  adds), Add/Sub (align to min e by bit-shift, sign-magnitude add/sub), Sign.
- A point is 4 bigints (X,Y,Z,W). Constructors COMPOSE:
    TrivialHPointBI(v)     = (x,y,z,1)          [d0, W==1, identity generator]
    CramerHPointBI(planes) = Cramer 3x3 dets    [d1, matches Intersect3Planes]
    ChordBI(a,b,c,d)       = meet(join(a,b),join(c,d)) [d2, cross-of-crosses]
  Deeper constructors nest ChordBI on chord operands (dD). Shallow operands pass
  the identity generator (W==1 trivial, or a d1 point where a d2 is expected) -
  the owner's "identity element when they do not need the degree".
- Predicates are the SAME determinant regardless of operand depth:
    Orient3D_BI(4 pts)  = 4x4 Leibniz det * sign(prod W)   [W==1 -> d0 orient3d]
    Orient2D_P2(3 pts)  = 3x3 det * sign(prod W)           [axis-dropped 2D]
- PARAMETERIZATION for the landing: template<int DEPTH> sets (a) the fixed
  bigint/accumulator limb width kW(DEPTH) (the prototype uses std::vector; the
  landed form uses a fixed array = totality-by-construction, no allocation), and
  (b) the filter constant path. Constructors of depth > DEPTH are not
  instantiated. DEPTH=1 compiles to the SAME arithmetic as the landed kernel; the
  theory lanes' max depth D plugs in as DEPTH=D.

BIT-IDENTITY RAIL (non-negotiable): the depth-0 and depth-1 instantiations compute
the SAME exact integer determinant as the landed HomogOrient3DSign<true> /
HomogOrient2DExact, so the SIGN is identical by construction (a well-defined
integer has one sign). Verified as output-bit-identity (0 diff), not instruction-
identity - the landed width-3 MulMagN and the width-8 Poly path are the
instruction-identical forms; the bigint prototype proves the arithmetic agrees.
INCIDENTAL (not isolated, directional): the d1 run (1e6) took ~6m dominated by
the landed Poly monomial expansion (HomogOrient2DExact, up to 1296 monomials each
via MulMagN<8>), while the DEEPER d2 bigint chord run (1e6) took ~22s with no Poly
path - consistent with the term-explosion the owner forbids also being a runtime
cost the compositional bigint form avoids. A clean isolated benchmark was not run.

## 3. FILTERS (per-depth construction-aware, the methodology extended)

PRIMARY: the running EBD forward-error bound (homog-design's construction-aware
filter) is DEPTH-GENERAL by composition. EBD = {value, abs-error}; EIn(err 0),
EAdd/ESub (err += errs + u|v|), EMul (err += |a|errb+|b|erra+errs + u|v|). The
filter propagates EBD THROUGH the SAME construction the exact bigint does
(ECramerHPoint -> EChord -> EOrient2DFilter_P2); certified iff |det.v| > det.err
AND every W certified. Being a RUNNING bound it needs NO per-depth constant - the
construction depth is baked into the propagated error. Verified: 0 wrong certs at
d1 (1e6), d2 one-nested (1e6), d2 three-nested (2e5).

STATIC form (if a compile-time constant is preferred): C(D)*u*Pdet, Pdet the all-
abs companion (every input |.|, every subtraction -> addition, a monotone upper
bound on every intermediate and the term sum). The op-count K along the deepest
monomial path gives C(D) ~ gamma_K: d1 K~20 -> C=32 (homog-design, measured
16.18); each nesting level adds the join (mul+sub) + meet (mul+sub) op-band, so
d2 one-nested K~45 -> C=64, d2 three-nested K~82 -> C=128. The static C is
CONSERVATIVE-certified but per-depth; the running EBD subsumes and tightens it.

NEGATIVE CONTROL (the naive bound, depth-general): the naive final-determinant
permanent (treat the point coords as exact inputs, C*u*perm) is UNSOUND at every
depth beyond its derivation depth. In the wedge/chord regime the constructed
coords are ~eps by O(1) cancellation, so the final permanent collapses to ~eps^k
while the error floor stays ~u -> ratio blows up. MEASURED at d2 with the d1
constant C=32: 7613 WRONG certifications / 1e6 (vs EBD 0). This is the degree-9
"unsound by 1.4e15" lesson generalized: the filter MUST be construction-aware and
per-depth; a single static permanent bound is never total across depths.
