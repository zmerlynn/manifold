## Log

### BLOCKER FINDING: the directed swap fails the openscad edge-pairing rail

Baseline (pristine, e1): openscad test PASSES (~17-19s), 0 open edges.

Experiment ladder (build-act3 Release, MANIFOLD_DEBUG=OFF; each = 1 build + 1
openscad run under E1_ENGINE, ulimit -v 6000000 timeout 900). All experiments
reverted; tree is pristine at 4181ce97.

1. STOCK SWAP (7027 -> TriangulateIdx(pidx,eps), allowConvex=true, no option):
   FAIL. Fatal = "unresolvable sheet contact" (SplitTouchingSheets, overlap3:130
   open edge fwd!=bwd), NOT the BuildImpl IsManifold gate. 45 open edges.
   triFail=0, dustCell=0 (not a triangulation FAILURE - the tris are produced
   fine; their emitted DIRECTED edges don't pair).

2. The open edges cluster at multi-sheet T-junctions (fan=3: 3 faces on one edge)
   at vertex clusters that are sub-eps apart (e.g. x=-17.7969, z=-206.942, y in
   {-2.69840..-2.69855}, a ~1.5e-4 span at coord scale ~207).

3. Per-cell diagnostics (E1_TRICMP, comparing e1::Triangulate vs stock on the
   SAME loops, all 5089 cells):
   - undirected boundary-edge multiset (odd multiplicity): 0 cells differ. Both
     triangulators emit the IDENTICAL loop-boundary edges. No leaf is culled.
   - e1 returns false: 0 cells. e1 partial-cover (area mismatch): 0 cells.
   - exactly-zero-area (sd==0 wrt Nrep) leaves: 0 in BOTH (the 2D-collinear
     leaves are 3D-NON-collinear, sd!=0; the "collinear-leaf emission" gap named
     in b3reuse is not the mechanism here).
   -> per-cell the two triangulations are boundary-identical, area-identical,
      e1-never-fails. The leaf-preservation premise does not match the data.

4. TEST A (classify uses e1 `tris`, emission uses stock triangles): FAIL, same
   45 opens -> the gap is in the EMITTED triangle set, not the classify centroid.

5. Emitted-triangle diagnostics (E1_TRIDBG): stock produces cwT=15 exact-CW
   (s2 = e1::O2 < 0, i.e. FOLDED) triangles across the 3145 emitted cells;
   colT=3; badCover=0 (signed-area sum matches e1 everywhere). The CW folds and
   the diagonalization differences all land in NEAR-DEGENERATE DUST cells: dumped
   failing cells have loopA (2x signed area) = 2e-13, 7e-14, 4e-12, 1.9e-8, 7e-6
   - at/below the weld scale. These are non-epsilon-valid loops; stock's
   tolerance EarClip gives a valid-BOUNDARY but folded/re-diagonalized partition.

6. ROOT CAUSE. The emission (overlap3:7376-7389) orients each emitted triangle
   by sd = dot(3D-normal, Nrep). For a dust cell (loopA ~ 1e-13) sd is numerical
   NOISE - and so is the loop's shoelace SIGN (the existing LoopShoelace comment
   at ~5723 documents exactly this: micro cells far from origin have garbage
   sign). e1 nonetheless pairs because its EXACT, deterministic diagonalization
   produces near-mirror triangles across a shared dust edge, so the two cells'
   sd values are ANTI-correlated and the sd-flip emits the shared edge
   anti-parallel. A different (tolerance) triangulation decorrelates the two
   sides -> the shared boundary edge is emitted the SAME direction on both ->
   open edge. This is the exact-vs-tolerance predicate gap, at the dust scale.

7. Attempted fixes, all FAIL:
   - Uniform per-cell orientation via exact 2D O2 winding, calibrated from the
     largest sub-triangle's reliable sd: 45 opens (keepCCW calibration is itself
     noise when the whole cell is dust).
   - allowConvex=false (force EarClip, drop the convex-fan): 45 opens (the fan is
     not the cause; the tolerance earclip alone reproduces it).
   - Dust-skip: skip emitting cells with extent-width < 0.99*eps: 57 opens
     (WORSE - the dust cells are LOAD-BEARING; dropping them opens the neighbours
     that paired against them, exactly the code's documented dust-rule hazard).

CONCLUSION. The swap as directed (resolver cell triangulation -> shared
polygon.cpp tolerance triangulator, with a leaf-preservation option) does NOT
achieve the openscad "STILL RESOLVES" rail. The blocking gap is NOT leaf culling
(boundaries are byte-for-byte the same set) and NOT a triangulation FAILURE that
the demotion would skip - it is that e1's EXACT diagonalization is load-bearing
for consistent orientation of the near-degenerate dust cells at multi-sheet
T-junctions, and no tolerance triangulator + emission/orientation/dust knob I
tried reproduces it. The b3reuse de-risking (areaMatch 1e-9, worstOver 5.6e-9,
"overlapCells=0") measured area MAGNITUDE, which is ~1e-13 for these folds and
below its witness threshold - it did not (and said it did not) measure the
DIRECTED edge-pairing that SplitTouchingSheets enforces. That caveat is where
the plan breaks.

DESIGN FORK for the owner (did not build either - needs a decision):
  (a) Keep e1 but RELOCATE it into polygon.cpp as an opt-in EXACT triangulation
      mode (shares the file / the exact O2 predicate; boolean3 keeps the default
      tolerance path). This is "one triangulator module" but NOT "the same
      algorithm with a flag" - it does not delete e1, it moves it. Faithful to
      the unification SPIRIT, not the letter ("delete the e1 earclip").
  (b) Accept that the resolver's exact earclip stays resolver-owned (the b3reuse
      verdict: SHAREABLE-W-ADAPTER but "NOT recommended, correctness risk high").
  (c) A deeper redesign of the dust-cell emission so orientation is derived from
      an exact GLOBAL rule (shared across adjacent cells) rather than per-cell sd
      - would make emission triangulator-agnostic, but is research-grade and not
      what was scoped.

Recommendation: (a) or (b). Not forcing a broken swap. Parts 1 (the OFF-default
polygon.cpp option) and 3 (the demotion) are only worth building once the swap
target is decided, since their whole purpose is to serve the swap.
