## 0. THE ONE-PARAGRAPH THESIS

The ATTACK grafts triple points into the PER-FACE overlay (EmitSeamedFace runs
RemoveOverlaps2D on face f alone, and a constructed crossing is back-projected onto
face f's plane). Three faces meet at one triple point, so the point is built THREE
times, in three frames -> three double-rounded 3D images AND three independent radial
subdivisions. That inconsistency is arrangement INCOMPLETENESS at the vertices - the
exact analog of the shares-vertex-skip edge-incompleteness that reg3d-wjump /
reg3d-7863c1 already closed on GT7863/GT7081/PokedCube (with NO new emission rule).
The arrangement-vertex-first design enumerates the triple points ONCE globally, builds
each canonically from its plane triple, and threads the SAME vertex into every
incident face's overlay. What this lane established by MEASUREMENT (section 4): the
121 holes split into >=50 that sit exactly at triple points (the per-face-construction
artifact, closed by the tripwire-FREE once-only core B1) and a far-hole residue
(68 astronomically distant from any triple) whose cause is confounded by dropped-
triangle geometry - it may be triple-caused (still B1-closable) or the ATTACK's
genuine everted/high-cover second wall. So the design's real contribution is
STRUCTURAL: it SEPARATES a cheap, tripwire-free once-only-WELD/cell-consistency fix
(B1) from any exact-RADIAL fix (B2, the tripwire), where the ATTACK bundled them and
priced the whole thing behind "one tripwire decision." The measurement REFUTES my
initial strong "the holes are dominantly an artifact" claim for the majority, and
leaves the exact size of the true second-wall residue to one decisive follow-up
(build B1, re-count) - with a reg3d-wjump-precedent prior that it is small.

## 1. WHY PER-FACE IS THE WRONG ALTITUDE (the mechanism, precisely)

A triple point T = {f,g,h} sits on three planes. In the arrangement it is a
0-cell where three 1-cells (the seam lines L_fg = plane(f)/\plane(g), L_fh, L_gh)
and the incident 2-cells (sub-faces of f, g, h) meet.

The current EmitSeamedFace (overlap3.cpp L1801) processes ONE face at a time:
  - projects face f + its seams (A.faceSeams[f]) to 2D via a face-local frame pf,
  - RemoveOverlaps2D subdivides the seams at their mutual crossings,
  - a subdivision vertex with no input preimage is the triple point (B3, L1848).

Three independent failures follow from doing this three times:
  (i)  POSITION: canon3 = pf.origin + u*e1 + v*e2 lands on plane(f) only. Face g's
       image lands on plane(g). The two agree only up to the double rounding of two
       different back-projections -> up to ~eps apart (measured: 5 survive >eps on
       openscad, oscad-f4 twin-scan).
  (ii) SUBDIVISION: L_fg is split at T on BOTH faces f and g, but at the two
       independent 2D crossings, so the sub-edge endpoints along L_fg are not the
       same 3D points across f and g until they weld.
  (iii)RADIAL/CELL: the local sectors around T (which sub-cells exist, in what
       order) come from two independent RemoveOverlaps2D runs; near T the cells are
       thin (three lines converging), so the per-cell centroid winding probes on f
       and on g can straddle inconsistently.

BuildImpl's eps-weld already fixes (i) and (ii) for the within-eps majority (that is
why the ATTACK's twin-scan finds only ~5 surviving twins). What survives the weld is
(iii): a sub-face retained on f whose 3D-adjacent partner on g was dropped, leaving
L_fg's radial fan unbalanced = an OPEN edge. This is why the holes are DOMINANTLY
non-twin (ATTACK measurement) and yet still present: they are combinatorial, not
positional.

reg3d-wjump's lesson (docs/Regularize3D.md, closure plan pt 3) is the precedent: the
GT7863/GT7081/PokedCube "unbalanced fan / open boundary / w spans negative" wall was
NOT an emission-rule wall; it was arrangement incompleteness (dropped seams from the
shares-vertex skip). Completing the arrangement made the EXISTING mult-1 witness rule
emit correctly - "decision-completion 2 is SUBSUMED, no new emission rule." The
per-face triple-point graft reintroduces exactly that incompleteness one dimension up
(at 0-cells instead of 1-cells). The fix is the same shape: COMPLETE the arrangement.

## 2. THE DESIGN (arrangement-vertex-first, two stages)

Global-once construction lets the fix split into a tripwire-FREE core (B1) and a
tripwire-GATED refinement (B2). B1 is the whole bet; B2 is only reached if B1's
measurement shows a residual near-tangent radial ambiguity the corpus forces.

### 2.1 Data structures (new)

    // A seam now remembers the partner face whose plane cut it (needed to name
    // the triple {f,g,h}).  4 bytes per seam.
    struct BuildSeam { vec3 p0, p1; int other; };   // + int other

    // Canonical triple-point identity = the sorted face-triple.  Two of {f,g,h}
    // coplanar => not a genuine triple (a 2-plane edge) => never keyed.
    struct TripleKey { int a, b, c; };               // a<b<c, operator< for map

    struct TriplePoint { vec3 pos; };                // once-only 3D (see 2.3)

    // Built once per component, after RecordSeams:
    std::map<TripleKey, TriplePoint> tripleTab;      // ~151 distinct on openscad
    std::vector<std::vector<const TriplePoint*>> faceTriples;  // per face: its Ts
    // plus, per face, the 2D projection of each incident T (filled lazily in the
    // face frame inside EmitSeamedFace).

### 2.2 Call sites / pipeline changes

  RecordSeams (overlap3.cpp ~L1254, ~L1645):
    - push `other` with each seam: `A.faceSeams[i].push_back({p0,p1, j})` and the
      symmetric `{p0,p1, i}` on face j. One field, two lines.

  NEW EnumerateTriplePoints(A) (new ~90 LOC, called from EmitComponentBoundary
  before the per-face loop):
    - for each face f, for each unordered pair of seams (s from g, t from h), g!=h,
      test proper 2D crossing in f's frame (level-0 orient2d, the SAME predicate
      RemoveOverlaps2D uses). On a crossing, insert sorted(f,g,h) into a set.
    - for each distinct TripleKey, construct pos = Intersect3Planes (2.3), store in
      tripleTab; append &T to faceTriples[f], [g], [h].
    - NOTE this is the SAME crossing enumeration RemoveOverlaps2D already does per
      face; we run it once up front only to NAME the triples and dedup them 3->1.
      (Alternative: harvest from the first face's RemoveOverlaps2D pass and dedup
      by TripleKey; identical result, avoids a second orient2d sweep. Either is
      cheap - the per-face seam counts are 1..34, oscad-f4 MEASUREMENT 2.)

  EmitSeamedFace (overlap3.cpp L1801, the surgical change). PRODUCTION FORM =
  PRE-SPLIT (dodges the fuzzy-match unsoundness of FM2):
    - project each incident T in faceTriples[f] to 2D: qT = (dot(pos-a,e1),
      dot(pos-a,e2)). Insert qT as an EXPLICIT input vertex of the face overlay
      with canon3 = T.pos (the GLOBAL point), and SPLIT each incident seam (f,g)
      into sub-segments at the qT of every triple {f,g,*} on it, ordered along the
      seam. Feed the pre-split seam segments + the registered triple vertices to
      RemoveOverlaps2D.
    - Now every crossing RemoveOverlaps2D re-detects at a triple eps-merges onto the
      already-registered qT, so pos2in.find SUCCEEDS with the global canon3 - no
      constructed-vertex fallback. A subdivision vertex that STILL has no input
      preimage is then a genuine unbuilt case (a >2-sheet radial 0-cell or a bug):
      fail closed, distinctly named. (On the corpus this never fires - every B3
      vertex is a named 3-plane triple.)
    - everything downstream (ExtractCells, per-cell winding, witness-rule retain) is
      UNCHANGED. The cells are still per-face 2D; only the shared 0-cell's 3D image
      is now once-only, so adjacent sub-faces on f and g carry the identical vertex
      and their fans balance.
    - CHEAP PROTOTYPE FORM (what this lane MEASURES): keep the prototype's
      getOrAdd2D but replace the per-face back-projection with a lookup of the
      incident T whose qT matches within eps. Same effect on the corpus (triples
      macroscopically separated), fewer LOC, but a fuzzy match - not the production
      choice.

  No change to FoldCoplanarClusters, EmitCleanFaces, BuildImpl, SplitTouchingSheets.

### 2.3 The once-only construction (B1, no new predicate FORM)

    Intersect3Planes(f,g,h):  pos = the double solution of the 3x3 system
      n_f . (x - a_f) = 0,  n_g . (x - a_g) = 0,  n_h . (x - a_h) = 0
    via Cramer over the input normals n_* = cross(b-a,c-a) and offsets. ONE
    evaluation, symmetric in (f,g,h) by the sorted key, so all three incident faces
    read the IDENTICAL bits. This is the once-only rule RESIDUAL-1 demanded, met
    STRUCTURALLY (one construction keyed by identity), not by a positional dedup.

  Critically B1 adds NO new predicate FORM: Intersect3Planes is a construction
  (like SegPlanePoint at L1231), not a decision. The 2D crossing test and the
  winding classify are the SAME level-0 orient2d/orient3d already in the tree. The
  winding probe near a thin triple-point cell already rides the reg3d-c2bx WindingAt
  filter-0 -> Orient3DExactSign escalation (RobustWinding at L1875 calls WindingAt),
  so a near-tangent cell centroid is decided exactly by the EXISTING blessed caller,
  or it is a genuine tie and fails closed. B1 therefore stays inside the standing
  tripwire (one predicate, one implementation).

### 2.4 B2 (tripwire-gated, reached ONLY if B1 leaves forced radial holes)

If the measurement (section 4) shows open edges surviving B1 at genuine near-tangent
triple points - where the RADIAL ORDER around T (which sub-faces meet, hence which
cell a thin centroid belongs to) is not double-decidable - then the residual needs
the EXACT orientation of the CONSTRUCTED point against nearby features. That is a
second predicate FORM: orient3d(T, a, b, c) with T a 3-plane intersection, outside
the domain of the current Orient3DExactSign (total only on INPUT doubles).

Substrate choice for B2 (the fork, answered from this vantage in section 3):
plane-based symbolic-rational T, orient3d generalized to accept it, evaluated on the
EXISTING adaptive-width integer accumulator. This is one new FORM but ZERO vendored
code - strictly cheaper than the ATTACK's "vendor Shewchuk predicates.c (4-5k LOC)".

## 3. THE SUBSTRATE FORK, FROM THE GLOBAL-ONCE VANTAGE

Does global-once construction change which substrate is natural? YES, decisively.

The ATTACK framed the fork as {vendored Shewchuk expansions on input doubles} vs
{memoized exact rationals}. But the ATTACK builds the point PER FACE and DISCARDS its
identity - all it keeps is a rounded double. Given only a rounded double, exact
orientation requires re-expanding it (Shewchuk expansions), and the expansion has
already lost the exactness the moment the point was rounded: orient3d on the rounded
triple point can flip sign vs the true point. So on the per-face substrate, neither
option is clean.

Global-once construction CARRIES the identity {f,g,h}. The triple point is then
NATURALLY a plane-based symbolic vertex: T = the exact rational solution of the three
input-coefficient planes, stored as (integer numerator vec3, integer denominator).
orient3d(T, p, q, r) becomes a polynomial in the input mantissas and the plane
coefficients - degree-bounded, sign-evaluable on the SAME integer accumulator the
existing ExactOrient3D uses (orient-attack: "each e-coefficient is a signed sum of
products of the coordinate mantissas over an adaptive-width accumulator"). So:

  - global-once makes the PLANE-BASED SYMBOLIC RATIONAL the natural substrate;
  - it is the MINIMAL tripwire crossing: extend the existing ~100-line integer
    orient3d to a symbolic-point argument, no vendored arithmetic, no Shewchuk;
  - and it is reached ONLY in B2, i.e. only if the corpus forces a near-tangent
    radial tie. If B1 closes openscad, ZERO tripwire is crossed.

This is the substrate choice: PLANE-BASED SYMBOLIC RATIONAL (not vendored Shewchuk),
and only in B2. B1 needs no exact-point predicate at all.

## 4. THE HIGHEST-VALUE QUESTION: are the 121 holes an artifact?

Hypothesis (this lane): the 121 open edges are DOMINANTLY per-face
inconsistency at the triple points (mechanism 1.iii), i.e. an artifact of the
per-face graft, NOT a genuine winding-jump>=2 / everted second wall. If so they are
localized AT the triple points and B1 (global once-only, no tripwire) closes them.

Counter-hypothesis (the ATTACK's reading): the holes are genuine dropped faces on the
everted (w_above in [-2,-1]) / high-cover (up to +3) strata, needing the winding-jump
re-emission - a real second wall, independent of triple-point consistency, so located
AWAY from triple points.

DECISIVE CHEAP MEASUREMENT (run in /tmp/f4-design-b, prototype + F4B_DUMP
instrumentation): dump every unbalanced-fan (open-boundary) edge and classify each
endpoint by distance to the nearest per-face triple-point image.
  - open edges with an endpoint AT a triple point (<=1eps) -> triple-localized ->
    artifact -> B1 closes.
  - open edges with NEITHER endpoint near a triple point (>16eps) -> a genuine
    everted/high-cover wall B1 does not reach.

MEASUREMENT (run: /tmp/f4-design-b, per-face prototype + F4B_DUMP, openscad through
the real entry, from-scratch Release build). Census at the emission wall:

  F4B_CENSUS: triplePtImgs=453 openEdges=121 bothAtTriple=14 oneAtTriple=36
              neitherNear=71
  F4B_HIST nearerEndpointDist(eps): <=1:50 <=16:0 <=1e3:1 <=1e5:2 >1e5:68

Read:
  - 453 per-face triple images (= ~151 distinct x3, confirms the ATTACK), 121 open
    edges (confirms the ATTACK's unbal=121).
  - 50/121 open edges have an endpoint AT a triple (<=1eps): bothAtTriple 14 +
    oneAtTriple 36 = 50 = the h1 bucket. These are UNAMBIGUOUSLY the per-face
    triple-construction artifact - the fans opened where the three per-face images
    disagreed. B1 (global once-only + pre-split) closes THESE.
  - 71/121 open edges have BOTH endpoints off every triple; of those, 68 have both
    endpoints >1e5 eps (astronomically) from ANY triple, with a CLEAN GAP (0 in
    (1,16], 1 in (16,1e3], 2 in (1e3,1e5]).

THE CONFOUND (why the far 68 are NOT decisively a second wall, and NOT decisively an
artifact): a dropped sub-face TRIANGLE whose apex vertex sits AT a triple has its
opposite (base) edge far from that triple. openscad coordinates are large and eps is
tiny, so a single large dropped triangle at a triple contributes a near-T open edge
(the h1=50 bucket) AND a far-far open edge (the >1e5 bucket) - producing exactly this
bimodal near/far split with a clean gap (a triangle has no edge at intermediate
distance from its apex). So distance-from-triple CANNOT separate "far edge of a
triple-caused dropped triangle" (still B1-closable) from "genuinely independent
everted/high-cover wall" (the ATTACK's winding-jump residue). The confound is
fundamental to ANY distance proxy; the position-only once-only is a no-op post-weld
(BuildImpl already welds the within-eps images, ATTACK twin-scan), so there is NO
cheap proxy - the decisive test is to BUILD B1 (once-only + pre-split, cell
consistency) and re-count. That is the ~120-180 LOC design itself, past this lane's
"cheap" bar.

ARGUMENT (independent of the measurement, in case it is ambiguous): on a COMPLETE and
CONSISTENT arrangement the mult-1 witness rule (retain cell iff w_above==0) emits a
CLOSED oriented boundary for ANY winding distribution, negative and high-cover
included. Proof shape: {w_S>=1} is a well-defined integer super-level set of a
single-valued coupled field; the boundary of a super-level set of a consistent
integer field on a valid cell complex is automatically a closed oriented surface.
Holes appear ONLY where the complex is invalid: an edge with an incomplete radial fan
(a missing 0/1-cell) or a cell with a misclassified winding. The per-face graft makes
the complex invalid at every triple point (mechanism 1.iii). Negative winding per se
does NOT open a boundary - the witness rule DROPS a w_above<0 cell, and a dropped
cell's neighbor is dropped too unless the arrangement between them is inconsistent.
So "w_above in [-2,+3] with 482 negative cells" is NOT evidence of a second wall; it
is evidence the region is deeply everted, which a consistent arrangement handles by
correctly dropping both sides. This is the SAME misattribution reg3d-wjump corrected
once (it read incompleteness as an emission wall); the ATTACK's twin-scan rules out
mechanism 1.i (surviving position twins) but NOT 1.iii (radial inconsistency that
welds in position but mismatches in cells), and then collapses "not a twin" into
"genuine second wall".

WHERE THE ARGUMENT COULD BE WRONG (honest): if B1 leaves open edges at genuine
near-tangent triples, the residual is a real radial-order ambiguity = B2 (the
tripwire). The measurement decides whether that residual is empty on openscad.

  - Fail-closed posture preserved: an unmatched constructed vertex (no incident named
    triple) is the genuine >2-sheet radial 0-cell (banked, reg3d-radial) -> fail
    closed, distinctly named, never a silent resolve.

## 7. TOP 3 FAILURE MODES (adversarial with myself)

FM1. B1 DOES NOT CLOSE - a residual thin-cell winding graze at triples fails closed.
  Even with once-only T, the cells around a near-tangent triple are thin; a per-cell
  centroid can land in the filter-0 band. RobustWinding rides the c2bx escalation, so
  it is decided exactly OR is a genuine tie -> fail closed (not a hole, not wrong).
  Outcome if this bites: openscad flips from F4 (121 holes) to a NARROWER
  DirtyComponentUnresolved at the winding probe = strictly better (the GT7081 story),
  and B2's exact-radial predicate is the completion. Still zero-oracle-wrong. This is
  the most likely partial outcome and it is still a win (narrower pin), not a loss.

FM2. THE 2D-MATCH FROM SUBDIVISION VERTEX TO GLOBAL T IS AMBIGUOUS. If two distinct
  triples project within eps on face f (two triple points nearly collinear in f's
  frame), the getOrAdd2D lookup could bind a crossing to the wrong T.pos -> a wrong
  3D vertex -> a self-fold the R1/R2 gate is blind to (docs R1). Mitigation: openscad
  triples are macroscopically separated (114/131 >1e4*eps, oscad-f4), so the 2D
  images are separated too; but the ROBUST design does not match by position at all -
  it PRE-SPLITS each seam at its triples using the projected T as an explicit input
  vertex (with T.pos as its canon3) BEFORE RemoveOverlaps2D, so the crossing vertex
  is an INPUT-preimage vertex, not a constructed one, and no fuzzy match is needed.
  (The position-match is the cheap prototype; pre-split is the production form.)
  If two triples genuinely fall within eps, BuildImpl would weld them anyway, so the
  bind is consistent with the downstream weld - not a new unsoundness.

FM3. THE MISATTRIBUTION IS MINE, NOT THE ATTACK'S - there really is a second wall.
  If the measurement shows open edges AWAY from all triples (neither endpoint near a
  triple), then negative/high-cover strata genuinely open under the mult-1 rule and
  reg3d-wjump's "no new emission rule" does NOT generalize to openscad. Then B1 is
  insufficient and the ATTACK's winding-jump>=2 re-emission is real. I hold this as
  the live falsifier and let the measurement rule. My prior (reg3d-wjump precedent +
  the closed-boundary-of-a-superlevel-set argument) is that this bucket is small, but
  it is exactly the claim a best-of lane must not assume.
