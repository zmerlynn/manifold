# Perf investigation - profile + one byte-identical win

Codex gpt-5.6-sol profiled the resolver; coordinator verified + landed.

## Phase profile (per resolve)
- GT7081 joined ~126s/component: registry BUILD dominates, and within it SEAM
  ENUMERATION is 80-100s. Flood/emission are milliseconds.
- siA ~11.3s: BUILD ~8s (of which ~4.2s is per-round engine setup), consume ~2s.
- openscad ~12.5s test: RE-GATE 9.4s dominates.

## LANDED (byte-identical, +8 lines)
- Re-gate grid scan pair-dedup: a large triangle spans many spatial-grid cells,
  so the same (i,j) pair was checked from every bucket (1.06M visits = 663K
  unique pairs). Added a `seen` set keyed on the pair; predicates are pure and
  first-encounter order retained => output byte-identical. openscad 12.5s -> 7.0s
  (re-gate 9.4 -> 3.8s). Verified canonical from scratch: corpus 29/29, openscad
  7.2s, GT7081 joined 248.6s; geometry hashes identical before/after.

## DEBUNKED by measurement
- Colliderizing the seam enumeration (the s2-b3reuse lead): 1.7% SLOWER on
  GT7081, reverted. The inline bbox filter already drops disjoint pairs, and the
  22-35M candidate pairs GENUINELY have overlapping boxes (dense twin corridor) -
  a spatial broadphase has nothing to prune. Helped siA marginally only.

## Clarification (the hot path is NOT exact arithmetic)
GT7081's seam-enum cost is the COUNT of candidate pairs x cheap DOUBLE per-pair
rejection (bbox test + farOneSide plane-side la::dot). The exact machinery
(sos::) runs only on the small subset surviving both filters; exact escalation
stays rare (parts-per-million, filter-first). The wall is the O(nTri^2) box-close
pair count from the near-tangent twin geometry, not the kernel.

## Findings left for review (opt-in, not landed)
- Per-component setup (grouping, triangle boxes/BVH, input-vertex identity) is
  rebuilt every BUILD round AND again for CONSUME, though it depends only on the
  input. Hoisting to immutable per-component state could remove 2 of 3 setup
  passes (siA spends ~37% there). A state-lifetime refactor - needs its own
  byte-identity crucible.
- GT7081 seam work: no easy win (geometry-bound; broadphase can't help). Only
  levers are exact-predicate allocation reduction / stronger memoization.
- Flood/emission parallelism: not worthwhile (milliseconds).
