# PAIRDIAG: why input-exact overlay faces fail to pair EVEN AMONG THEMSELVES

Branch explore/sweep-plane-3d-v5, local HEAD 1568e9e0. Work in rsync copy
/tmp/pairdiag (from-scratch Release, -j8). Canonical READ-ONLY except this
notebook. Diagnosis of the coverage lane's fact (coverage-1784207835): opens rise
MONOTONICALLY with exact-overlay coverage (21 -> 31 -> 34 -> 114), and at
all-seamed coverage every seamed face uses the input-exact overlay yet the emitted
boundaries do not weld pairwise.

## METHOD

Enabled the all-seamed lever EX2_ALL in the copy; ran openscad with the boundary
census (STITCH_CENSUS = per-face subdivision each face places on each shared
segment), the open-edge dump (F4B_OPENDUMP), and the winding-cell dump
(EX2_CELLDUMP). Extended the open-edge dump to print BOTH endpoints at full
precision (copy only, +5 lines in SplitTouchingSheets). Added a clean-face
boundary census CLEAN_CENSUS (copy only, +12 lines in EmitCleanFaces) so
seamed-vs-clean shared edges are diffable. Reproduced exactly:
`EX2_ALL EX2_SKIPB3 F4B_DUMP`: large comp okfaces=573 b3faces=1 openEdges=114;
F4B_OPEN fan1=98 fan2=4 fan3=12; ties=0 overlaps=0 slivers=0.
Default (no lever): okfaces=574 openEdges=21; fan1=14 fan3=6 fan4=1; ties/overlaps=0.

Grouped every shared boundary line by welded endpoints (weld 1e-9, in the clean
gap between eps=3.52e-10 and the model's 7.8e-9 min feature separation), diffed the
two-plus incident faces' ordered split lists, then classified each open edge by
whether its reverse partner is missing due to a subdivision mismatch or a
retention gap. Classification is STABLE across weld 4e-10..6e-9 and across the
seamed-only / seamed+clean carrier sets.

## DIVERGENCE TAXONOMY (task classes)

Overlay (EX2_ALL, 114 opens):
- (a) SUBDIVISION divergence  = 45   (fan1-dominant)
- (d) RETENTION / pairing gap = 65   (53 fan1, 12 fan>1)
- lone-carrier (partner is fold/uncaptured or true gap) = 4
- (b) ORDER = 0        (chains are param-sorted; never reordered)
- (c) IDENTITY / alias = 3 shared segments (bit-different point within eps;
      subsumed by the eps-weld; minor)

Default baseline (21 opens): (a)=10, (d)=11 - the SAME two classes.

Segment level: of 1733 shared segments, 1709 subdivide IDENTICALLY, only 24
diverge - i.e. the divergence is concentrated on the crowded near-coincident
cluster's super-concurrent edges, not spread over the mesh.

### (a) SUBDIVISION divergence - the archetype

The crowded cluster has SUPER-CONCURRENT edges: e.g. the vertical line
x=-17.7969, y=-2.69846 is carried by 14 face-segments. A genuine arrangement
vertex on that line - the triple {228,230,232} at z=-206.94166653906586 - is
EXACTLY on the line (x,y match to ~1e-15). Faces 230,232 (which carry planes
230/232) split there; faces 229,257,259,262 span PAST it to the input vertex
z=-206.942 (3.3e-4 away) WITHOUT splitting. The two emitted boundary carriers end
at points 3.3e-4 apart, so neither pairs -> two open edges (the fractured halves).

CONFIRMED cause with GRAZE_DROP=1: the on-line triple {228,230,232} is dropped by
`onCarrier` from f=229,257,259,262 (2..3 times each) AND from segments of f=230/232
whose carrier partner is not 228/232. `onCarrier` (overlap3.cpp:3977-3984) uses
plane-membership {planeId[f], carrierQ} as a proxy for "exactly on this carrier",
which is ASYMMETRIC at a super-concurrency: an on-line vertex whose 3-plane
provenance names only 3 of the N>3 concurrent planes is injected into the named
faces and dropped from the rest, fracturing the shared line.

Compounding: face-kinds use DIFFERENT injection rules. Seamed faces
(pushChain, overlap3.cpp:3985-4051) inject registry junctions filtered by onCarrier
plus skip own ends plus per-face weld/completion (wedge, 4079-4296). Clean faces
(EmitCleanFaces:5450-5452) inject EVERY registry junction UNFILTERED, no skipEnds.
So a seamed/clean shared edge diverges by construction.

### (d) RETENTION / pairing gap - the residual

65/114 opens are on lines where all coincident seamed+clean carriers AGREE on
subdivision (stable across weld tol), yet the fan is imbalanced (mostly fan1).
Cell dumps show retention is LOCALLY CORRECT: the emitting face keeps a genuine
boundary cell (w+=0,w-=1) while the coincident neighbour's cell is correctly
dropped as BURIED (f323 w+=1,w-=2) or EXTERIOR (f332 w+=-1,w-=0), on large
non-sliver cells (area 1e17..1e19 eps^2, winding reliable). F4B ties=0 overlaps=0
across every run rules out mis-orientation / double-material. So the boundary
sub-edge's reverse partner is genuinely absent: it coincides with a neighbour's
buried/exterior wall, and no OTHER coincident boundary face supplies the reverse.
Per-face retain-cells + weld + radial fan-pair cannot pair coincident multi-winding
sheets - manifold pairing there needs a per-edge decision the per-face model does
not make.

### triangulation is NOT a source

TriangulateIdx -> EarClip / TriangulateConvex add NO Steiner points; the emitted
triangles' boundary edges ARE the cell boundary sub-edges (per-face uedges), with
interior diagonals only. So triangulation-internal vertices never land on a shared
boundary. The shared-seam subdivision comes entirely from per-face uedges (wedge) /
RemoveOverlaps2D (default), NOT from triangulation.

### canonical registry vs own cell walk

OWN cell walk. A global junction registry (A.junctions) exists, but every face
consumes it through a face-KIND-specific filter (onCarrier for seamed, unfiltered
for clean) plus per-face weld/completion/seamTriples, so no two coincident faces
derive an identical shared-line subdivision. There is no per-LINE canonical
subdivision that all incident faces read.

## ROOT CAUSE

ONE mechanism family: per-face-INDEPENDENT emission (each face is its own
axis-dropped 2D arrangement; subdivision by a face-kind-specific junction filter,
retention by a per-cell winding probe), with the eps-weld (BuildImpl:275-368) +
radial fan-pairing (SplitTouchingSheets:77-256) as the ONLY cross-face coordination.
At the crowded near-coincident cluster (many coplanar/collinear walls meeting on
super-concurrent lines, at many winding levels) this coordination is insufficient:
  - the subdivision facet (class a): onCarrier's plane-membership on-line proxy
    (overlap3.cpp:3977-3984, applied 3991-3997) drops genuine on-line vertices from
    the concurrent faces whose planes are not among the vertex's 3-plane provenance,
    and clean faces use a different (unfiltered) rule - so coincident sub-edges get
    mismatched endpoints;
  - the retention facet (class d): each face keeps its boundary cells independently
    (EmitSeamedFace:5016-5041, EmitCleanFaces:5389-5414); a boundary sub-edge whose
    coincident neighbour is at a different winding depth (correctly buried/dropped)
    has no coincident boundary partner, so it stays unpaired.

## DOES IT EXPLAIN THE DEFAULT 21

YES. The default baseline shows the identical two-class split (10 subdivision /
11 retention), same file:line mechanism (pushChain+onCarrier feed the default
RemoveOverlaps2D too, via stitchDefault at :3967/:3991; clean faces same). The
overlay does not introduce a new failure - it AMPLIFIES this one: the wedge path
preserves more distinct near-coincident split points (skips MergeVerts), so more
super-concurrent lines fracture, hence opens rise monotonically 21->31->34->114
with coverage. It is one mechanism all the way down.

## FIX SHAPE (design only)

Replace per-face arrangement + hope-it-welds with per-LINE shared subdivision +
per-EDGE coordinated pairing:
1. CANONICAL PER-LINE SUBDIVISION. Key every arrangement vertex to the exact
   carrier LINE(s) it lies on, via an EXACT on-line predicate (NOT plane-
   membership, which is asymmetric at super-concurrencies). For each boundary line
   collect ONCE the ordered set of all vertices exactly on it; every incident face
   (seamed, clean, fold) subdivides its boundary at EXACTLY that shared ordered
   list. Coincident sub-edges then share welded endpoints by construction, which
   dissolves class (a) and unifies the three face-kind injection rules. Retire
   onCarrier's proxy and the per-face weld/completion.
2. COORDINATED PER-EDGE PAIRING. With coincident sub-edges identical, decide the
   {w>=1} boundary PER SHARED SUB-EDGE across all its coincident sheets at once
   (the SplitTouchingSheets radial fan already has the right shape - order the
   sheets around the edge by dihedral, emit matched boundary pairs), instead of
   each face independently retaining cells. This dissolves class (d): coincident
   multi-winding sheets get a single per-edge pairing decision.

This is the "exact-rational 2D arrangement engine / global coordination" the
coverage lane named (docs E1). The diagnosis pins WHY per-face emission cannot
substitute for it: at a coincident multi-winding cluster, manifold pairing is a
per-edge property, and shared-line subdivision must be canonical per-line, neither
of which a per-face arrangement can guarantee.
