# ACT3 lane B (empirical): flood-winding + canonical seam orders on real corpus

Owner-commissioned third-act probe. Prototype the two exact-kernel-elimination
mechanisms against the exact pipeline as differential oracle (zero-oracle-wrong).
Canonical READ-ONLY; all builds in /tmp/act3-b (from bc350f70, from-scratch cmake
Release, -j8, PAR=OFF). Instrumentation is env-gated (ACT3_CENSUS), shadow-only
(no output change), so the suite stays green while measuring.

   da/db/o + PrecomputeSeedSign), EG class (EdgePiercesTriSoS guard),

2. Seam-graph flood differential in EmitSeamedFace + fold: for every arrangement
   cell, capture exact w_above/w_below; build intra-face cell adjacency; classify
   each interior edge as seam(partner g)/boundary; test
   - M1 |dw_above| across a seam adjacency == 1 (the seam graph carries unit deltas)
   - M4 w_below - w_above == cover (both-sides +1 for mult-1: second probe is free)
   - M2 the lateral partner side-test (flood's delta plane-test) filter-certified?
   - M3 does the certified side-flip presence match the winding jump (sign proxy)
   - M5 extremal-cell outward winding == 0 (combinatorial seed value)
3. Seam 1D order census: per seam, does face f's 2D crossing order match the
   canonical 3D arclength order, and the partner g's 2D order?

## The delta SIGN is the metric-sign trap (mission's flagged risk)

pred_bad = the certified far-centroid plane-side flip DISAGREES with the (always
present) winding jump. It rises with partner near-tangency: siA/siB ~3%, GT7863
~17%, GT7081 ~32%, openscad ~12%. The cause: for a near-coplanar partner g, g's
plane is nearly parallel to face f, so BOTH +nHat-offset probes land on the same
side of g's plane even across the seam - the plane test is certified (filt0=0) but
it is the WRONG QUANTITY. The delta MAGNITUDE is combinatorially 1 (robust); the
delta SIGN must come from the seam's own provenance (partner orientation + which
2D side of the seam the cell is on), NOT from re-probing g's plane with an offset
centroid. This confirms the mission's framing ("delta from provenance/face
orientations") and refutes the naive "sign(dot(centroid_disp, n_g))" source: it is
not near-uncertain (filter certifies it) but it is wrong up to a third of the time
on the near-tangent twins. The right source is combinatorial and metric-free.

## Combinatorial seed (M5)

Extremal-cell outward winding == 0 on siA/siB/GT7863/Entangled*/BarsCrossZ/openscad
(seed value confirmed). PokedCube and GT7081 report extWout=1 - my proxy takes the
max-x SEAMED-cell centroid, which on everted / twin geometry is an interior seam,
not the true hull-extremal vertex. The combinatorial seed needs the true extremal
mesh vertex (outward w=0 from face orientation), not a seam-cell centroid; the
value argument holds where the proxy lands on the hull.

## The GT7081 fire attribution (corrects the orient-attack premise)

orient-attack-1784086942 attributed GT7081's ~11.7k winding fires to "WindingAt"
and named flood as the escape. Path attribution shows the fires are ~99% in the
CLEAN-FACE winding path (EmitCleanFaces), not the seamed path:
  GT7081 (full test, 2 calls): waTot da=22538, byPath[seam=129 clean=22409]
  (99.4% clean). (The count is ~2x orient-attack's 11729 because it includes the
  clean-path WindingAtCands escalations that notebook's WindingAt-only probe did
  not; the SOS/EG figures match exactly, confirming the harness.)
The seam-graph flood reproduces the seamed-face winding perfectly (unit deltas,
certified) - but the seamed path is NOT where GT7081's mass fires. The mass is the
clean-face winding, and clean faces carry NO seams, so the seam graph does not
reach them. Eliminating the GT7081 mass needs cross-face (mesh-edge dihedral)
flood connectivity to carry the winding onto clean faces - the unbuilt piece
(memory flags arrangement-completion as research-grade). The seam-graph flood
alone zeroes the seamed-path winding fires (small); the clean-face mass survives
until mesh-edge propagation is built.

## RAIL 2: canonical seam 1D orders

seamOrder multi = seams with >=2 interior splits (order matters at all).
- Resolving carriers: multi=0. Every seam has 0-1 interior splits; ordering is
  trivial, nothing to disagree on.
- openscad: multi=232 (the wedge fans). f3dBad=0 AND fgBad=0 on all 232 - face f's
  2D order equals the canonical 3D arclength order AND equals partner g's 2D order
  in EVERY multi-split seam.
Provable and observed: projecting a 3D line into a face plane is affine along the
line, so the per-face 2D parameter is monotonic in 3D arclength - the orders
CANNOT disagree except by FP rounding, and none did (0 flips corpus-wide). A
canonical per-seam order would change NOTHING bitwise: each face already consumes
that order. This mechanism is a no-op win (dedupes work, changes no output) - not
the escape the exact kernel needs.

## Perf sketch

GT7081 (PAR=OFF) is winding-dominated (2-5 min; wall times 309s/128s are
confounded by concurrent-job contention, so not a clean flood-vs-ray comparison -
and no timed flood was built). The defensible concrete number is the EXACT-FIRE
reduction: ray-cast winding fires Orient3DExactSign 22538 times on GT7081; a
correct flood fires it 0 times in the winding class (every seam delta is unit +
combinatorial, every lateral plane-test is filter-certified: cert filt0=0). So
the winding-class exact fire count is 22538 -> 0 - conditioned on the clean-face
cross-face connectivity being built (99.4% of that 22538 is clean-path). Flood
also replaces every winding QUERY (an O(candidate) BVH ray-walk, thousands of
them) with O(cells) integer additions (GT7081: 336 cells) - an asymptotic
collapse, but the clean-face queries are the mass and they are not on the seam
graph.

## Honest boundary of what was validated

Shadow differential validated the flood's INGREDIENTS against the oracle with zero
disagreements on resolving carriers: unit seam deltas (magnitude), lateral
plane-test certifiability, both-sides redundancy, and the combinatorial seed value
(where the proxy lands on the hull). It did NOT assemble an end-to-end flooded
field and diff it bitwise to the exact winding at every probe - that needs (a) the
provenance-based delta SIGN (identified as the fix for pred_bad, not built) and
(b) cross-face mesh-edge connectivity to reach clean faces (research-grade,
unbuilt). So "flood value == exact value everywhere" is supported at the
invariant level, not yet demonstrated as a full field.

## Verdict

- Flood on the seam graph: mechanism SOUND on corpus (unit deltas 0 exceptions on
  resolving carriers; lateral plane-tests certified everywhere). Sign must be
  combinatorial (provenance), not a metric re-probe (pred_bad up to 32% refutes
  the dot-product sign).
- Exact-fire elimination: seam-graph flood zeroes the SEAMED winding fires; the
  GT7081 mass is CLEAN-FACE winding, unreachable by the seam graph - needs
  cross-face mesh-edge flood (unbuilt / research-grade).
- Canonical seam orders: zero disagreements corpus-wide; per-face orders already
  equal canonical. No-op win, not a kernel escape.
