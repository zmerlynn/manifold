under PAR=ON". This does NOT reproduce. Running the base BINARY directly:

both. Likely root cause: the "base = emission under PAR=ON" reading came from the
F4B_PERFACE census on the HEAD binary (which still PRE-SPLITS, so it reaches
emission) being mistaken for true base behavior; the real base has no pre-split

my builds, so this is a prose inaccuracy only - the pin flip and the
"PAR-consistent at HEAD" claim (the load-bearing part) are correct. Recommend the
owner correct the aside; it does not block the push.
