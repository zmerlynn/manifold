## Pipeline stage map (src/overlap3.cpp)

RemoveOverlaps3D -> PrepareArrangement (canon+seams) -> SweepEmit:
  1. BuildSlabs (overlap3_sweep.cpp): slabs + per-slab pieces; the demoted
     conflict counter lives here.
  2. resolvers: one SlabResolver per slab. Ctor has an O(pieces^2) cluster loop
     (line ~555) and holds tracks_ map + planar_ vec per slab (all held at once).
  3. EmitCaps -> ComputeCap per pair-canonical critical: RemoveOverlaps2D over
     both slabs' extended pieces; appends cap tris to `emitted`.
  4. EmitStrips -> ZipperEmit per piece per built slab; appends strip tris.
  5. BuildImpl(emitted): eps-weld via hash grid + `std::set<tuple> seenTris`
     (2-3x memory amplifier over the raw emitted vector) -> CreateHalfedges ->
     2-manifold gate.

Blowup candidates: (a) tens of thousands of slabs each emitting modest tris ->
large linear `emitted`; (b) one pathological slab/cap with quadratic pieces;
(c) BuildImpl seenTris+grid amplification. Instrumented all boundaries.

sectionEdges COPY, sectionVerts COPY, seamTracks, pieces) in the `slabs` vector held
ALL AT ONCE for the downstream caps+strips stages. In the near-degenerate bands each
built slab straddles ~1000-3000 faces, so it retains ~that many of each structure.
Total at completion ~30M pieces + ~30M edges + ~30M segments -> ~15GB (matches the
lane's 17GB VSZ). Growth shape: memory ~ LINEAR in cumulative retained pieces,
concentrated in a few dense bands; NOT one quadratic loop. Emission (EmitCaps /
EmitStrips / BuildImpl) is NEVER REACHED. The lane's "downstream emission blowup"
LOCATION is factually wrong; the blowup is in slab CONSTRUCTION.
